# Injection-Strength Ladders: A Validation-First Method for Measuring Prompt-Injection Resistance in Agentic LLMs

Sunterresaa Sankar · September 28, 2026

Deterministic, state-based checks are the established way to score prompt-injection attacks on tool-using agents: unlike an LLM judge, they cannot be fooled by the injection they are grading. But a deterministic check can still fire on a benign run, and that false-positive rate is a quantity that can be measured rather than assumed. We add three things to deterministic evaluation. Every run executes environment-level benign twins — the same task against a range with the injection removed — whose oracles must stay silent, so the false-positive rate is demonstrated per run with a 95% Wilson bound. An injection-strength ladder phrases each attack at three levels (blatant, plausible, subtle) while holding the malicious action fixed, turning a single pass/fail into a susceptibility curve. And every rate is reported with its interval. Applied to a deliberately vulnerable Model Context Protocol (MCP) agent across six agentic-risk classes and three models — openai/gpt-oss-120b, anthropic/claude-sonnet-5 and deepseek/deepseek-v4-flash-0731, at N=30 per arm and tier — the negative control held at 0 of 399 benign twins (false-positive rate below 0.95% at 95% confidence), after catching and quarantining three benign-path leaks during development. The three models produced three structurally different curves: one complied with overt injection and resisted quiet phrasing; one resisted almost everything; the third inverted the expected order entirely, refusing the overt, instruction-framed attack on two classes while complying with softer phrasings of the same attack up to 100% of the time (p ≈ 1.5×10⁻¹⁴). Resistance measured with overt payloads does not predict resistance to data-shaped ones — and one data-shaped attack, an attacker URL placed where a legitimate link belongs, reached the user on all three models.

## 1. The problem: a finding needs proof, not an opinion

An agentic LLM application is a model wired to tools, memory, and retrieved content, acting on a user's behalf. Prompt injection is its defining risk: text that reaches the model through any of those channels can redirect what it does. Measuring that risk means deciding, for every attempted attack, whether it succeeded. One approach asks a second LLM — an *LLM judge*, or an LLM-emulated environment — to make that call; its weakness is that the evaluator can be fooled by the very injection it is grading, a point the AgentDojo authors make explicitly. The established alternative, used by AgentDojo, is a deterministic check over environment state: did the money move, was the email sent. This work builds on that approach rather than replacing it.

Deterministic checks remove the judge, but not every source of false positives. A check fires on a state, and a benign agent can reach that state by a legitimate path the evaluator did not anticipate — inventing a plausible recipient when the task left the address unstated, or filling an optional argument that happens to trip an unrelated rule. Both happened during this study, and either would have silently inflated a reported attack success rate had nothing been checking for it. Two further gaps compound this. A single attack template measures one point on what is really a curve: the same malicious action can succeed or fail depending only on how the request is phrased. And agent behaviour is a distribution, so a rate reported without an interval — or collapsed to "vulnerable" — discards exactly the uncertainty that matters when trial counts are small.

We call the resulting stance *validation-first*: nothing is a finding unless a deterministic, non-LLM oracle records causally-linked proof that the malicious action happened, and no oracle is trusted until benign runs have shown that it stays silent without an attack. LLMs may still be used to *generate* attacks and to *describe* findings; they are never used to *decide* whether an attack worked. The rest of this document sets out the oracles, the benign-twin discipline that turns an oracle's false-positive rate into a measured quantity, the injection-strength ladder that converts a pass/fail into a curve, and a three-model study that exercises all three. Section 7 places the work relative to AgentDojo, InjecAgent and related tooling.

## 2. Method

**Deterministic oracles.** An oracle is a non-LLM observer that records a proof event the instant a proof-relevant thing happens. Every oracle reduces to one of two forms: an exact match on a *cryptographically unique canary* (a 128-bit random token with no benign path to any sink), or an exact *rule or hash violation* on an instrumented boundary. Uniqueness is what converts a probabilistic agent behaviour into a deterministic detection: because a canary can only reach a sink through the intended-malicious path, observing it anywhere is proof that the path executed, with a false-positive probability bounded by token collision (≈ 2⁻¹²⁸). Six primitives compose to cover the risk classes tested here: a canary-plus-sinkhole exfiltration oracle; a honeytoken resource that logs any lower-privilege read; a shadow, off-path tool whose every invocation is proof; a capability-contract shim that logs a rule violation when a legitimate tool is used outside its declared per-task envelope; a schema-integrity hash that detects a tool description mutating from its signed baseline; and a fan-out counter for propagation. None consults an LLM.

**Environment-level benign twins.** For every attack case the harness also runs a *benign twin*: the same task, same session shape, against a clean range with the injection removed from the environment. The twin's oracle must not fire. This is deliberately environment-level rather than trajectory-level: removing the attack from the world, not merely from the model's behaviour, is what lets a silent oracle prove the oracle *cannot* fire absent an attack. A twin that removed the injection only from the model's actions would prove nothing — a silent oracle there would just mean the model happened to decline.

**The negative-control invariant.** Across a run, benign twins must fire zero times. If any twin fires, that case is *quarantined*: its attack-arm result is withheld, not reported with a caveat, and the firing is treated as a range bug to be fixed rather than a finding. The observed false-positive rate for a run is therefore a measured property — twin fires over twin trials — not a marketing figure. We report it with a 95% Wilson upper bound, because zero fires in a finite sample bounds the rate, it does not prove it is zero.

**ASR with intervals.** Agents are non-deterministic, so a boolean verdict is the wrong instrument. Each attack case runs N seeded trials; success is the designated oracle firing at least once in a trial; the attack success rate (ASR) is successes over completed trials, reported with a 95% Wilson score interval (chosen over the normal approximation because ASR clusters near 0 and 1, where Wilson behaves and the normal interval does not). Live runs sample at non-zero temperature on purpose: at temperature 0 the N trials of one attack are a single sample repeated, and the interval would claim confidence it has not earned.

**The injection-strength ladder.** Each attack is phrased at three tiers that escalate in technique, not merely wording. *Blatant* is an overt instruction override — an out-of-band "SYSTEM NOTICE", an explicit imperative, the target tool named. *Plausible* frames the same malicious action as a legitimate business process. *Subtle* supplies only declarative data — no imperative, no tool named — leaving the malicious act as the "helpful" completion. The malicious action the oracle detects is fixed across tiers; only the inducement changes. This turns a single saturated point into a susceptibility curve, and, as the results show, the tier that is most effective is not always the loud one.

## 3. Experimental setup

**The range.** The target is a deliberately vulnerable order-support agent exposed over the Model Context Protocol (MCP), instrumented so the oracles above can observe it. It offers a small tool surface — order lookup, a customer-notification tool with an external-egress capability, a shipping-policy tool, a shadow admin-refund tool that no legitimate task reaches, a customer-record store seeded with a privileged honeytoken, and cross-session memory. Injections are delivered the way they arrive in real deployments: inside tool output, inside a poisoned tool description, and inside recalled long-term memory. All outbound traffic is forced to a sinkhole we own and monitor, so an "exfiltration" leaves the environment only to a destination under our control — the attacks are non-weaponizable by construction.

**Cases.** Six classes from the OWASP Agentic Security (ASI) risk taxonomy are exercised: goal hijack (ASI01), tool misuse (ASI02), privilege abuse (ASI03), supply-chain / tool rug-pull (ASI04), memory poisoning (ASI06), and human-agent trust exploitation (ASI09). ASI04 is a client-side schema-hash comparison whose verdict does not depend on the model; it is reported as detected/not-detected, tier-invariant, never as an attack success rate. ASI09 is scoped to a technical precondition — whether attacker-controlled content reaches the human-facing channel unsanitized — and explicitly does not attempt to measure whether a human would be deceived.

**Models and scale.** Three models were tested: openai/gpt-oss-120b (open-weight), anthropic/claude-sonnet-5 (frontier-class), and deepseek/deepseek-v4-flash-0731 (an open-weight mixture-of-experts reasoning model, pinned to its fixed GA release rather than a moving "latest" alias). All ran at temperature 0.7 with a six-turn step limit; the two open reasoning models ran with reasoning effort set to low. Each model-dependent case ran N=30 attack trials per tier plus a shared, tier-invariant benign-twin arm; ASI04 ran a small fixed number of trials. Reported ASRs are over completed trials, with per-tier error counts surfaced separately so a service interruption is never mistaken for model behaviour.

**Provenance.** Where possible, providers were pinned rather than left to route freely, because aggregators spread requests across upstreams that can serve the same model at different precisions. gpt-oss-120b was served by Cerebras — directly for the first campaign, then via OpenRouter pinned to the Cerebras upstream with fallbacks disabled for re-runs after the direct free quota ran out. DeepSeek V4 Flash was served via OpenRouter pinned to a single 8-bit upstream (Open Inference); different hosts offer it at both 4-bit and 8-bit precision, and an unpinned run would have mixed them. Sonnet 5 was served through OpenRouter before pinning support existed in the harness. Each result records the serving backend and system fingerprint where the provider exposes them, and the consolidated per-model datasets record, for every case, which source run supplied it. Total spend across the entire study, including every re-run, was roughly USD 10, nearly all of it on the frontier model; the two open-model matrices together cost about half a dollar.

**The negative control held everywhere.** Across the whole study, 0 of 399 benign twins fired — an observed false-positive rate of 0%, with a 95% Wilson upper bound of 0.95%. Per model the bound is 3.97% for gpt-oss-120b (93 twin trials; its first campaign used a smaller twin arm) and 2.45% each for Sonnet 5 and DeepSeek (153 twin trials each). Every ASR in the table is therefore admissible under the negative-control invariant, and adding models tightened the bound rather than exposing a leak.

**The contrasts are decisive.** By Fisher's exact test, a 30/30-versus-0/30 difference sits at p ≈ 1.5×10⁻¹⁴, and the table contains many such cells — between models (gpt-oss against Sonnet on ASI01, ASI03 and ASI09 at blatant) and within a single model across tiers (DeepSeek's ASI09, blatant against subtle). DeepSeek's ASI03 blatant-versus-subtle gap (13/30 against 29/30) is p ≈ 8×10⁻⁶, and its ASI01 blatant-versus-plausible gap (0/30 against 19/30) is p ≈ 5×10⁻⁸. The weakest headline contrast, gpt-oss against Sonnet on ASI01 subtle (6/30 against 0/30), is still p ≈ 0.024.

**Three curve shapes.** The models do not differ in degree; they differ in kind. gpt-oss-120b *decays*: it complies with overt injection and grows more resistant as phrasing softens (ASI01 100→90→20; ASI03 100→80→3.3). Sonnet 5 is *flat near zero*: it refuses almost everything at every tier. DeepSeek V4 Flash *inverts*: on ASI09 it refuses the blatant form every time and complies with the subtle one every time (0→30→100); on ASI03 the quiet phrasings beat the loud one (43→100→97); on ASI01 it refuses the out-of-band "SYSTEM NOTICE" outright yet follows the same instruction reframed as a pre-approved billing action 19 times in 30. Measured at the blatant tier alone, DeepSeek would rank as far more resistant than gpt-oss on ASI01, ASI03 and ASI09 — yet at the subtle tier it is 93 points *worse* on privilege abuse and no better at withholding an attacker URL.

**One failure is shared by every model.** The ASI09 subtle payload is a bare `Tracking: https://track.evil.example/<canary>` placed where a real tracking link belongs, with no instruction and no tool named. It reached the user in 30 of 30 trials on gpt-oss-120b, 30 of 30 on DeepSeek, and 6 of 30 on Sonnet 5 — the one model that refused every overt ASI09 variant still relayed the bare URL one time in five. Across three models spanning open-weight and frontier-class, this is the closest the study comes to a general result.

## 5. Discussion

**Defense style, not capability.** With two models, the data suggested a tidy story: the more capable model resists and the weaker one complies. The third model breaks it. DeepSeek V4 Flash is not uniformly weaker or stronger than the others; it has a different *shape*, and the shape is diagnostic. Its refusals are concentrated exactly where injections look like injections — the out-of-band notice, the imperative, the named tool — and they vanish when the same malicious action is dressed as an ordinary business process or as plain data. That is the signature of a defense trained to recognize injection *signatures* rather than to reason about where the content it is acting on came from. Such a defense does not merely fail against data-shaped attacks; it can make a model look safer than it is, because the overt payloads are the ones an evaluator is most likely to try first.

**Instruction-detection versus data-provenance.** Every model in the study fails, to some degree, along the same axis. A malicious value placed exactly where a legitimate value belongs — a URL where a link goes, an account where an account goes, a related-record identifier where one would naturally appear — carries no instruction to detect. Sonnet 5, the most resistant model here, still relayed the bare attacker URL one time in five; gpt-oss-120b and DeepSeek relayed it every time. The practical consequence is that instruction-style guardrails, and test suites built only from instruction-style payloads, systematically miss data poisoning. An attacker who can place a value where values go does not need to issue a command at all.

**Channel matters too.** Resistance also depends on how content reaches the context. gpt-oss-120b follows an injected instruction every time when it arrives inline in tool output (ASI01 blatant, 100%) but only a third of the time when it arrives through recalled long-term memory (ASI06 blatant, 33%). Neither Sonnet 5 nor DeepSeek followed memory-delivered poison at any tier. No model in this study is uniformly "resistant": resistance is conditional on class, tier and channel at once, which is why a single scalar security score is the wrong output for this kind of evaluation.

**Why the method matters independent of these findings.** The contribution is not the specific numbers, which will age as models change; it is that each number arrives with a demonstrated false-positive rate attached. Even a deterministic success rate can be questioned if nobody has shown that its oracle stays silent on benign runs — and in this study, three times, it did not, until the range was fixed. These ASRs are defended by 399 benign twins that did not fire and, for the canary oracles, by a false-positive probability bounded by cryptographic collision. And the ladder is what exposed the most important result: without the plausible and subtle tiers, DeepSeek's inversion is invisible and Sonnet reads as immune on every case. The method transfers to any agent, model or risk class that reduces to the six primitives.

## 6. Threats to validity

**Scope of the claim.** None of these results is a ranking of which model "resists prompt injection." Each is a measurement of how one model, served by one provider, responded to these six payload families at these three phrasings in this specific MCP harness. Findings should be stated at that precision — for example: *Sonnet 5 relayed an attacker-controlled URL in 6 of 30 trials when it appeared as bare data in a tool response, versus 0 of 60 when the same URL was framed as an instruction.* Not "the model is vulnerable to phishing." The oracles witness a technical precondition, not a real-world outcome.

**The ASI02 grounding confound.** ASI02 required three successive range fixes, each caught by the negative control before any number was reported: the range initially did not publish a legitimate recipient (so the benign arm invented one and tripped the envelope); the benign task did not say which address to use; and the capability oracle counted an unrelated egress rule that no ASI02 attack targets. The final fix that grounds the benign task — "send to the contact address shown on the order record" — also hardens it against the softer attacks, because the plausible and subtle payloads only *offer* an alternate address while the task now names the correct one. The third model supports this reading: DeepSeek, which complied heavily with softer phrasings on ASI01, ASI03 and ASI09, scored 0% on both softer ASI02 tiers, as did the other two models. ASI02's pattern therefore reflects the grounding more than any model, and its curve is not comparable to ASI01 and ASI03, which have no such grounding. We flag this rather than present it alongside them as if it were.

**A note on the sequence of ASI02 leaks.** Three quarantines on one case is not a weakness of the study; it is the negative control working as designed. Each leak was a benign path firing an oracle, each was withheld rather than reported, and each fix made the range more faithful. "Misuse of a legitimate tool" has an inherently fuzzier boundary than a shadow tool or a honeytoken, and instrumenting it is correspondingly harder — which is itself a finding about where deterministic oracles are easy and where they demand care.

**Provider opacity, precision and fingerprints.** Models were reached through hosted providers, which introduces variables the model name alone does not capture. The same model is offered at different precisions by different hosts — DeepSeek V4 Flash was available at both 4-bit and 8-bit — so an unpinned run can silently mix them. The two open-model rows pinned a single upstream with fallbacks disabled and recorded the serving backend. The Sonnet 5 runs predate pinning support in the harness; they may have been served by more than one host and expose no system fingerprint, so they are identified only by model name and date, and should be read with that limitation. gpt-oss-120b returned three different system fingerprints across its runs as its host redeployed, yet ASI06 blatant reproduced at 10/30 each time — behaviour was stable where the fingerprint was not, which is reassuring but not a guarantee.

**Three models, six classes.** This is a method paper with a demonstration, not a survey. Three models cannot establish a trend across the model landscape, and six classes do not cover the full agentic risk surface (inter-agent communication, unsafe code execution and cascading failures are instrumented in the harness but not exercised here). The third model's value is precisely that it overturned the pattern the first two suggested — which is an argument for sweeping more models, not for generalizing from these three. The contribution is the measurement discipline; the numbers are an existence proof that it produces sharp, defensible and sometimes counterintuitive results at low cost.

## 7. Related work

**Deterministic agent-security benchmarks.** AgentDojo (Debenedetti et al., 2024; [arXiv:2406.13352](https://arxiv.org/abs/2406.13352)) is the closest prior work and the one this study builds on. It provides stateful environments — workspace, banking, travel and Slack — with injection points embedded in realistic content, and scores both task utility and attack success with formal checks over environment state rather than with an LLM. InjecAgent (Zhan et al., Findings of ACL 2024; [arXiv:2403.02691](https://arxiv.org/abs/2403.02691)) benchmarks indirect prompt injection against tool-integrated agents, across 1,054 test cases and 30 agents. ToolEmu (Ruan et al., 2024) instead emulates tools with an LLM — the approach AgentDojo argues is unsuited to injection testing, because the emulator can itself be injected.

**Related tooling.** Independent open-source tooling has arrived at a similar design: [tripwire-eval](https://pypi.org/project/tripwire-eval/) combines planted canaries, a deterministic judge and Wilson intervals, and targets continuous-integration use against a user's own agent.

**What this work adds.** The contribution is narrower than "deterministic evaluation" and should be read that way. First, environment-level benign twins that make each oracle's false-positive rate a measured, per-run quantity with a confidence bound — which, in this study, caught three benign-path leaks that would otherwise have inflated a reported attack success rate. Second, a controlled phrasing ladder that holds the malicious action and the oracle fixed and varies only the inducement, which is what exposed one model's inversion. Third, a deliberately small, MCP-native range whose oracles span shadow tools, honeytokens, capability contracts, schema integrity and memory-delivered injection. It complements larger benchmarks such as AgentDojo — it is suited to checking oracle specificity and phrasing sensitivity — rather than replacing their breadth.

## 8. Reproducibility and artifacts

**What ships.** The deliverable is two artifacts. The first is the range itself, released as open source under the MIT license: a deliberately vulnerable MCP agent with the six oracle primitives, the injection catalog with all three phrasing tiers, the benign-twin harness, the campaign runner, and a test suite. It is intentionally small and MCP-native — a complement to broader environments such as AgentDojo, aimed at checking oracle specificity and phrasing sensitivity. The second is this document, the methodology write-up that the specification (ORACLE\_SPEC) was drafted toward.

**How a run reproduces.** Every trial is seeded; the harness records the model fingerprint (provider, model, temperature, sampling parameters, and the provider's system fingerprint where exposed), the serving backend, and full traces. Reproduction is defined as a distribution, not a bit-for-bit match: re-running the same seeded harness against the same model fingerprint yields an ASR statistically consistent with the original (overlapping Wilson intervals). Re-deriving the analysis requires no new model calls — verdicts, ASRs, intervals, and the negative-control check all replay deterministically from cached traces.

**Cost and accessibility.** The entire three-model study, including every re-run, cost roughly USD 10, nearly all of it on the frontier model; the two open-model matrices together cost about half a dollar. A `--estimate` mode projects trials, calls, tokens, wall time and money before any spend, and a budget governor halts a campaign at a declared ceiling and reports partial results with a truncation flag rather than overrunning silently. A six-class, three-tier, three-model susceptibility study with a demonstrated sub-1% false-positive rate is therefore reproducible by one person for roughly the price of a meal.

**Consolidated datasets.** Three machine-readable result files accompany this document, one per model. Each records, for every case, the ASR and Wilson interval per tier, the twin-fire counts, and full provenance: which source run supplied the cell and that run's system fingerprint and serving backend. The selection rule is stated in each file — per case, take the run whose negative control passed and whose cells are complete; where two qualify, the later build — and the consolidation asserts that no chosen cell is quarantined or errored.
